## 题目：TCP 三次握手为什么需要三次而不是两次？
**答案**：两次握手只能确认客户端→服务端一个方向可达，服务端无法确认客户端收到了自己的 SYN-ACK，也无法确认客户端的接收能力；第三次 ACK 让双方都确认收发正常，并防止历史重复 SYN 建立错误连接。
**标签**：TCP,计算机网络,握手
**难度**：3
**频率**：high

## 题目：TCP 与 UDP 的主要区别是什么？
**答案**：TCP 面向连接、可靠、有序、有流量控制和拥塞控制，头部 20 字节起；UDP 无连接、尽力交付、不保证顺序，头部 8 字节，开销小、延迟低，适合实时音视频与 DNS 等场景。
**标签**：TCP,UDP,计算机网络
**难度**：2
**频率**：high

## 题目：HTTP/1.1 与 HTTP/2 有什么区别？
**答案**：HTTP/2 使用二进制分帧、多路复用、头部压缩（HPACK）、服务器推送；HTTP/1.1 是文本协议，浏览器对同域有连接数限制，存在队头阻塞，常用域名分片等优化。
**标签**：HTTP,计算机网络
**难度**：3
**频率**：high

## 题目：浏览器输入 URL 到页面展示经历了哪些步骤？
**答案**：URL 解析 → DNS 解析 → 建立 TCP 连接（HTTPS 再加 TLS 握手）→ 发送 HTTP 请求 → 服务端处理并返回响应 → 浏览器解析 HTML 构建 DOM、加载 CSS 构建 CSSOM、执行 JS、布局与绘制 → 合成与上屏。缓存、CDN、重定向会穿插其中。
**标签**：HTTP,DNS,浏览器
**难度**：3
**频率**：high

## 题目：DNS 解析的递归查询和迭代查询有什么区别？
**答案**：递归查询由本地 DNS 服务器替客户端一路问到最终结果再返回；迭代查询中服务器只给出下一步该问的服务器地址，由客户端继续查询。实际中客户端对本地 DNS 是递归，本地 DNS 对根/顶级/权威服务器是迭代。
**标签**：DNS,计算机网络
**难度**：2
**频率**：mid

## 题目：HTTPS 握手中中间人能否伪造证书？
**答案**：不能，除非 CA 体系被攻破或用户手动信任了恶意证书。浏览器校验证书链签名、域名、有效期与吊销状态；证书私钥签名需服务端参与，中间人拿不到私钥，无法完成 CertificateVerify。
**标签**：HTTPS,TLS,计算机网络
**难度**：3
**频率**：mid

## 题目：什么是 CIDR，如何判断两个 IP 是否在同一网段？
**答案**：CIDR 用“IP/前缀长度”表示网段，如 192.168.1.0/24。将两个 IP 分别与子网掩码做按位与，结果相同即在同一网段；前缀越短网段越大。
**标签**：网络,IP
**难度**：2
**频率**：mid

## 题目：进程和线程的区别是什么？
**答案**：进程是资源分配的基本单位，拥有独立地址空间；线程是 CPU 调度的基本单位，共享进程资源，切换开销小。线程间通信方便但需同步；进程隔离性好但通信成本高。
**标签**：操作系统,进程,线程
**难度**：2
**频率**：high

## 题目：死锁的必要条件有哪些，如何预防？
**答案**：互斥、持有并等待、不可剥夺、循环等待四个条件同时成立。预防可通过一次性申请全部资源（破坏持有并等待）、资源按序申请（破坏循环等待）、可抢占资源（破坏不可剥夺）等；也可用银行家算法做死锁避免，或检测后回滚。
**标签**：死锁,操作系统,并发
**难度**：3
**频率**：high

## 题目：操作系统中的用户态和内核态为什么要切换？
**答案**：内核态可执行特权指令、访问全部硬件与内存；用户态受限以防程序破坏系统。用户程序需要系统调用（文件、网络、进程等）时通过中断/陷入切换内核态，完成后返回；切换有上下文保存开销。
**标签**：操作系统,内核
**难度**：3
**频率**：mid

## 题目：虚拟内存的作用是什么？
**答案**：给每个进程独立的连续地址空间，屏蔽物理内存限制；支持按需调页与换出，实现内存隔离与保护，并可通过页表实现共享库与内存映射文件。
**标签**：操作系统,虚拟内存
**难度**：3
**频率**：mid

## 题目：LRU 页面置换算法如何实现？
**答案**：常用哈希表 + 双向链表：哈希表 O(1) 定位节点，链表头部为最近使用、尾部为最久未使用；访问时移到头部，容量满时淘汰尾部。
**标签**：操作系统,算法,LRU
**难度**：3
**频率**：mid

## 题目：MySQL 索引为什么使用 B+ 树而不是 B 树或红黑树？
**答案**：B+ 树非叶子节点只存键，单页能容纳更多键，树高更低、磁盘 IO 更少；叶子节点链表支持范围查询与顺序扫描；红黑树树高较高、磁盘随机 IO 多，且不适合范围扫。
**标签**：MySQL,索引,B+树
**难度**：4
**频率**：high

## 题目：什么时候索引会失效？什么是回表？
**答案**：对索引列做函数运算或隐式类型转换、以 % 开头的 LIKE、OR 连接非索引列、联合索引不满足最左前缀时容易失效。回表是二级索引查到主键后再到聚簇索引取整行，可通过对查询列建覆盖索引避免。
**标签**：MySQL,索引,优化
**难度**：4
**频率**：high

## 题目：MVCC 是怎么实现的？
**答案**：InnoDB 每行有隐藏的 DB_TRX_ID 与 DB_ROLL_PTR；更新时旧版本写入 undo log，回滚指针串成版本链。读时根据 ReadView（活跃事务集合）沿版本链寻找对当前事务可见的版本，从而实现一致性非锁定读。
**标签**：MySQL,MVCC,事务,数据库
**难度**：5
**频率**：high

## 题目：MySQL 事务隔离级别有哪些，分别解决了什么问题？
**答案**：读未提交（脏读）、读已提交（解决脏读，仍有不可重复读）、可重复读（InnoDB 默认，解决不可重复读，间隙锁缓解幻读）、串行化（全部解决，并发最低）。
**标签**：MySQL,事务,ACID
**难度**：3
**频率**：high

## 题目：redo log 和 binlog 有什么区别？
**答案**：redo log 是 InnoDB 的物理日志，循环写，用于崩溃恢复保证持久性；binlog 是 server 层逻辑日志，追加写，用于主从复制与数据恢复。两阶段提交保证二者一致。
**标签**：MySQL,日志,数据库
**难度**：4
**频率**：mid

## 题目：聚簇索引和非聚簇索引有什么区别？
**答案**：聚簇索引叶子节点存放整行数据，InnoDB 主键索引即聚簇索引；非聚簇（二级）索引叶子节点存放主键值，需要回表。MyISAM 索引叶子存放行地址，均为非聚簇。
**标签**：MySQL,索引,数据库
**难度**：3
**频率**：mid

## 题目：为什么推荐使用自增主键？
**答案**：自增主键单调递增，新行总插入 B+ 树最右侧叶子，页分裂少、写入局部性好；随机主键（如 UUID）会导致随机插入、页分裂与碎片，二级索引也更大。
**标签**：MySQL,主键,索引
**难度**：2
**频率**：mid

## 题目：Redis 为什么快？
**答案**：纯内存操作、单线程模型避免锁竞争与上下文切换、I/O 多路复用处理海量连接、高效数据结构（SDS、跳表、哈希表）、协议简单。
**标签**：Redis,缓存
**难度**：2
**频率**：high

## 题目：缓存穿透、缓存击穿、缓存雪崩分别是什么，如何应对？
**答案**：穿透是查询不存在的 key 每次都打到数据库，用布隆过滤器、缓存空值应对；击穿是热点 key 过期瞬间大量请求打库，用互斥锁重建或逻辑过期；雪崩是大量 key 同时过期或 Redis 宕机，用过期间错开、高可用集群、限流降级应对。
**标签**：Redis,缓存,高并发
**难度**：4
**频率**：high

## 题目：Redis 的持久化方式有哪些？
**答案**：RDB 定时生成内存快照，恢复快但可能丢数据；AOF 追加写命令，可配置 everysec（最多丢 1 秒）或 always，AOF 重写压缩体积。生产常用混合持久化。
**标签**：Redis,持久化
**难度**：3
**频率**：mid

## 题目：Redis 分布式锁如何实现？
**答案**：SET key value NX PX ttl 原子加锁，value 用唯一标识；释放时用 Lua 脚本校验 value 再删除避免误删；考虑锁续期与主从切换下的一致性（RedLock 或带 fencing token）。
**标签**：Redis,分布式,锁
**难度**：4
**频率**：high

## 题目：Redis 单线程为什么能处理高并发，多线程版本变化了什么？
**答案**：命令执行仍是单线程，依靠内存与 I/O 多路复用；Redis 6.0 引入多线程只用于网络 I/O 读写，命令执行保持串行，避免数据竞争。
**标签**：Redis,并发
**难度**：3
**频率**：low

## 题目：如何排查接口响应慢的问题？

## 题目：JVM 内存区域如何划分？
**答案**：线程共享：堆（对象实例）、方法区/元空间（类元数据）；线程私有：程序计数器、虚拟机栈、本地方法栈。JDK 8 起元空间使用本地内存。
**标签**：Java,JVM,内存
**难度**：3
**频率**：high

## 题目：JVM 垃圾回收算法有哪些？
**答案**：标记-清除（碎片多）、复制（新生代，无碎片但浪费空间）、标记-整理（老年代，无碎片但移动开销）、分代收集（按对象存活周期分治）。
**标签**：Java,JVM,GC
**难度**：3
**频率**：high

## 题目：CMS 和 G1 有什么区别？
**答案**：CMS 是标记-清除、以最短停顿为目标的老年代收集器，有记忆碎片问题；G1 把堆划分为 Region，可预测停顿、可增量回收，使用复制-整理避免碎片，JDK 9 起默认。
**标签**：Java,JVM,GC
**难度**：4
**频率**：mid

## 题目：volatile 关键字保证什么？
**答案**：保证可见性（写后对其它线程立即可见，通过内存屏障与缓存一致性）和禁止指令重排，但不保证原子性；常用于状态标志与双重检查单例。
**标签**：Java,并发,volatile
**难度**：3
**频率**：high

## 题目：synchronized 和 ReentrantLock 的区别？
**答案**：synchronized 是 JVM 内置锁，自动释放，支持偏向/轻量/重量级升级；ReentrantLock 是 AQS 实现的可重入锁，支持公平锁、可中断、超时、多条件变量，需手动 unlock。
**标签**：Java,并发,锁
**难度**：3
**频率**：high

## 题目：线程池的核心参数有哪些，内部如何工作？
**答案**：核心线程数、最大线程数、队列、线程工厂、拒绝策略等。提交任务先使用核心线程，满则入队，队列满则扩到最大线程数，再满则执行拒绝策略。
**标签**：Java,并发,线程池
**难度**：3
**频率**：high

## 题目：HashMap 的底层结构和扩容机制？
**答案**：JDK 8 起为数组 + 链表 + 红黑树；默认容量 16、负载因子 0.75，超过阈值扩容为两倍；链表长度 ≥8 且数组容量 ≥64 时树化。扩容时按 hash 高位判断，节点只分到原索引或原索引 + 旧容量。
**标签**：Java,集合,HashMap
**难度**：4
**频率**：high

## 题目：为什么重写 equals 必须重写 hashCode？
**答案**：哈希集合先按 hashCode 定位桶，再用 equals 判等。若二者不一致，等于的对象可能落在不同桶中，导致去重失效；一致的约定是相等的对象 hashCode 必须相同。
**标签**：Java,基础
**难度**：2
**频率**：mid

## 题目：什么是类加载的双亲委派模型？
**答案**：加载类时先委派父加载器，父加载器无法加载才由子加载器加载；优点是避免核心类被篡改并可共享类。Tomcat 等容器会打破委派实现隔离。
**标签**：Java,JVM,类加载
**难度**：3
**频率**：mid

## 题目：AQS 的原理是什么？
**答案**：以 volatile 的 state 表示同步状态，FIFO 双向队列维护等待线程，通过 CAS 修改 state 竞争，使用 LockSupport 阻塞唤醒；ReentrantLock、CountDownLatch、Semaphore 均基于其实现。
**标签**：Java,并发,AQS
**难度**：5
**频率**：mid

## 题目：Python GIL 是什么，对多线程有什么影响？
**答案**：CPython 的全局解释器锁保证同一时刻只有一个线程执行字节码，CPU 密集型任务无法多核并行；I/O 等待会释放 GIL，故 I/O 密集场景多线程仍有效；CPU 密集应使用多进程或原生扩展。
**标签**：Python,并发,GIL
**难度**：3
**频率**：high

## 题目：Python 中 list 和 tuple 的区别？
**答案**：list 可变、动态扩容、内存开销较大；tuple 不可变、长度固定、可哈希（元素都可哈希时）、创建更快，适合作为常量数据或字典键。
**标签**：Python,基础
**难度**：1
**频率**：mid

## 题目：Python 的装饰器原理是什么？
**答案**：装饰器本质是可调用对象，接收函数并返回新函数或包装器；利用函数是一等公民与闭包实现，functools.wraps 保留原函数元信息。
**标签**：Python,装饰器
**难度**：3
**频率**：mid

## 题目：Python 中浅拷贝与深拷贝的区别？
**答案**：浅拷贝只复制外层容器，内部对象仍是引用；深拷贝递归复制所有嵌套对象。copy.copy 与 copy.deepcopy 分别对应；切片赋值与 dict.copy 都是浅拷贝。
**标签**：Python,基础
**难度**：2
**频率**：mid

## 题目：生成器和迭代器有什么关系？
**答案**：迭代器实现 __iter__ 与 __next__；生成器是使用 yield 的简化迭代器，惰性求值、节省内存，可配合 send 实现协程。
**标签**：Python,生成器
**难度**：2
**频率**：mid

## 题目：asyncio 协程和线程有什么区别？
**答案**：协程在单线程内由事件循环协作式调度，遇到 await 主动让出，切换开销小，适合高并发 I/O；线程是抢占式调度、共享内存需加锁。阻塞调用会卡住整个事件循环，需用 to_thread 或线程池。
**标签**：Python,协程,并发
**难度**：4
**频率**：high

## 题目：Go 的 goroutine 和线程有什么区别？
**答案**：goroutine 是用户态轻量协程，初始栈约 2KB 可动态扩展，由 Go runtime 调度到少量 OS 线程上，采用 M:N 模型；创建和切换成本远低于线程，通信推荐通过 channel。
**标签**：Go,并发,goroutine
**难度**：3
**频率**：high

## 题目：Go 中 channel 的缓冲与非缓冲有什么区别？
**答案**：无缓冲 channel 的发送与接收必须同步配对（同步点）；有缓冲 channel 在缓冲未满可立即发送、未空可立即接收。关闭的 channel 接收返回零值与 false，向已关闭 channel 发送会 panic。
**标签**：Go,channel,并发
**难度**：3
**频率**：mid

## 题目：C++ 移动语义解决了什么问题？

**标签**：C++,移动语义
**难度**：4
**频率**：mid

## 题目：什么是虚函数和虚表？
**答案**：虚函数支持运行时多态；含虚函数的类有虚函数表，对象内保存指向虚表的指针，调用时通过虚表查找到实际类型实现，实现动态绑定。
**标签**：C++,虚函数
**难度**：4
**频率**：mid

## 题目：HTTP 状态码 301、302、304、307 有什么区别？
**答案**：301 永久重定向，302 临时重定向（历史上可能改写为 GET），304 协商缓存命中不返回实体，307 临时重定向且保持原方法与请求体；308 为永久且保持方法。
**标签**：HTTP,计算机网络
**难度**：2

## 题目：Cookie 和 Session 的区别？

## 知识：索引的最左前缀原则
**类型**：principle
**内容**：联合索引 (a,b,c) 像字典一样先按 a 排序、a 相同再按 b、再按 c 排序。查询条件连续包含最左侧列时才能利用索引定位；跳过 a 直接查 b 或 c 会退化为全表扫描；范围条件列之后的列无法继续用于索引定位，但可用于覆盖索引与索引条件下推。
**别名**：最左匹配,联合索引
**标签**：MySQL,索引

## 知识：MVCC 快照读
**类型**：principle
**内容**：InnoDB 为每行保存隐藏事务 ID 与回滚指针，更新产生的旧版本通过 undo log 串成版本链。快照读时以 ReadView 判断版本可见性：版本事务未提交、或已提交但晚于 ReadView 创建时不可见，沿版本链继续向前找。RC 每次读取新建 ReadView，RR 在事务第一次读时创建并复用，因此 RR 下可重复读。
**标签**：MySQL,事务,数据库

## 知识：缓存穿透、击穿与雪崩
**类型**：comparison
**内容**：穿透：查询必然不存在的数据，布隆过滤器拦截 + 缓存空值。击穿：单个热点 key 失效瞬间海量请求直达数据库，互斥锁重建缓存或逻辑过期。雪崩：大量 key 同时失效或缓存服务宕机，过期时间加随机、集群高可用、限流与降级。
**别名**：缓存三大问题
**标签**：Redis,缓存

## 知识：HTTP 缓存
**类型**：principle
**内容**：强缓存由 Cache-Control/Expires 决定，命中则不发请求；协商缓存由 ETag/If-None-Match 或 Last-Modified/If-Modified-Since 决定，未变更时服务端返回 304。HTML 一般短缓存或协商，带哈希文件名的静态资源可长期强缓存。
**标签**：HTTP,计算机网络,前端

## 知识：索引回表与覆盖索引
**类型**：concept
**内容**：InnoDB 二级索引叶子节点存主键值，查询列超出索引范围时需按主键回聚簇索引取整行，即回表。若查询需要的列都已经在索引中（覆盖索引），可直接从二级索引返回，避免回表；利用 explain 的 Extra 是否含 Using index 判断。
**标签**：MySQL,索引

## 知识：线程池的工作流程
**类型**：process
**内容**：提交任务 → 核心线程未满则新建核心线程执行 → 核心线程已满则进入工作队列 → 队列已满且线程数小于最大值则新建非核心线程 → 仍无法处理则触发拒绝策略（AbortPolicy、CallerRunsPolicy、DiscardPolicy、DiscardOldestPolicy 或自定义）。空闲的非核心线程超过 keepAliveTime 后被回收。
**标签**：Java,并发,线程池

## 知识：volatile 的内存语义
**类型**：concept
**内容**：写 volatile 变量时，之前的普通写不会重排到其后，且值立即对其他线程可见；读 volatile 时，其后的读不会重排到其前。底层通过内存屏障与缓存一致性协议实现。volatile 不保证复合操作的原子性，如 i++ 仍非线程安全。
**标签**：Java,并发,volatile

## 知识：死锁的四个必要条件
**类型**：concept
**内容**：互斥（资源一次只能被一个线程占用）、持有并等待（持有资源又申请其他资源）、不可剥夺（资源不能被强行抢占）、循环等待（存在等待环）。破坏任意一个即可预防死锁，例如按固定顺序加锁破坏循环等待。
**标签**：死锁,操作系统,并发

## 知识：进程与线程
**类型**：comparison
**内容**：进程是操作系统资源分配的基本单位，有独立的虚拟地址空间与资源；线程是调度的基本单位，同一进程内线程共享地址空间、代码段、数据段和文件描述符，各自有独立栈与寄存器。线程切换只需保存少量上下文，比进程切换轻量。
**标签**：操作系统,进程,线程

## 知识：HTTPS 握手

## 知识：TCP 流量控制与拥塞控制

## 知识：DNS 解析流程

## 知识：JWT 无状态认证

## 知识：Python GIL
**类型**：pitfall

## 知识：Go goroutine 调度
**类型**：principle
**内容**：GMP 模型：G（goroutine）、M（OS 线程）、P（逻辑处理器）。P 维护本地运行队列，M 必须绑定 P 才能执行 G；本地队列空时从全局队列或其他 P 偷取（work stealing）。阻塞的系统调用会释放 P，避免卡住整个调度器。
**标签**：Go,并发,goroutine

## 知识：Vue 3 响应式

## 知识：CAP 与 BASE

## 知识：MySQL 三种日志

**内容**：redo log：InnoDB 物理日志，环形写，崩溃后重放保证持久性；undo log：逻辑日志，保存旧值，支持回滚与 MVCC；binlog：server 层逻辑日志，一次事务一个事件流，用于主从复制与按时间点恢复。事务提交采用 redo 与 binlog 两阶段提交保证一致。
**标签**：MySQL,日志,数据库
