## 0. 阅读指南与实施基线

### 0.1 文档约定

- **里程碑**：M1 = P0，M2 = P1，M3 = P2，M4 = P3。
- **时区与“今天”**：数据库统一存 UTC 时间戳；业务日期字段使用 `YYYY-MM-DD`，按 `Asia/Shanghai` 本地日期计算。“今天”指用户本地日期，不是 UTC 日期。
- **题目**：`questions` 中的正式题或草稿；**待审项**：`pending_items` 中的候选内容。两者不是同一张表。
- **评分档位**：UI 只暴露三档：不熟、熟悉、精通；内部映射 q=2/4/5。
- **数据规模**：M1 目标 100–200 题，性能验收上限 500 题；M2 目标 5000 题。
- **代码与接口**：API 前缀 `/api/v1`；除登录和健康检查外均需认证；返回统一包 `{ code, data, message }`。
- **默认部署**：仅监听 `127.0.0.1`，单用户本地使用。

## 1. 项目概述

### 1.1 一句话定位

个人专属、AI 可选增强的八股文记忆 + 间隔重复（SM-2）+ 仿真模拟面试 Web 系统，支持**本地文档导入**与**定向爬虫采集**两种方式沉淀面经，结构化题库与独立知识条目库，本地优先部署，架构预留产品演进。

### 1.2 目标

解决八股文“背了忘、忘了背、不成体系、临场答不出”的问题，覆盖：

- 日常碎片化背诵；
- 面试前集中突击（含轻量冲刺视图）；
- 全真模拟面试（M3）；
- 面经通过本地导入 / 爬虫自动采集后待审入库。

### 1.3 成功指标（M1）

- 本地正式题库达到 **100–200 题**；最低来源门槛：爬虫审核通过 ≥20 题、本地导入审核通过 ≥20 题，其余由手动新建与导入补足至 100；
- 完成“筛选刷题 → 三档自评 → 错题本 → SM-2 到期复习”闭环；
- 每日到期复习队列可正常生成，且同一题当天只出现一次；
- **本地导入闭环**：Markdown / CSV / JSON 可导入，逐行报错，去重后进待审区，人工审核入库；
- **GitHub Markdown 爬虫闭环**：可配置源、采集、解析、去重、进待审区、人工审核入库；
- **知识库闭环**：导入/爬虫可抽取独立知识条目，≥20 条知识条目审核通过进入知识库，并与至少 20 道题建立关联；
- 无 AI、无外网 Key 时，题库、知识库、刷题、复习、错题本、统计、导入、爬虫待审流程完整可用；
- 数据可导出 Markdown / JSON，SQLite 文件可备份恢复；
- 前端至少覆盖：仪表盘、题库、知识库、刷题、复习、错题本、收藏夹、导入、爬虫任务/待审、统计、设置；
- 题库关键词搜索、个人笔记、考前冲刺视图可用；
- 规则打标可配置；用 20 条样例待审项验收，至少 15 条能给出至少一个建议标签或分类。

### 1.4 核心设计原则

1. **无 AI 也能完整使用**：AI 是增强项，断网 / 无 Key 时核心流程降级可用。
2. **Web 前后端分离**：FastAPI 提供 REST/JSON，Vue3 前端独立部署；业务逻辑全部在后端。
3. **题目与知识双产出、统一入口**：本地导入与爬虫采集走同一套清洗、去重、待审、审核管线，同时产出题目和知识条目。
4. **爬虫必选但必须可控**：只抓公开内容，限频、去重、待审，不自动直接入正式题库或知识库。
5. **题库与知识库结构化**：题目、知识条目、分类、属性、掌握度、复习计划全部入库，支撑筛选、统计和排程。
6. **本地优先、可演进**：M1 SQLite 单机可用，M2 视需要支持 PostgreSQL，不把路走死。
7. **单一事实来源**：待审内容只在 `pending_items`（题目/知识），正式题只在 `questions`，知识条目只在 `knowledge_points`；来源关系分别写入 `question_origins` 和 `knowledge_origins`。

### 1.5 关键口径定义

以下定义同时用于数据模型、筛选条件和统计接口，避免各章口径漂移。

| 概念 | 定义 |
|---|---|
| 未学 | `questions.status='active'`、未删除，且没有任何 `mastery_records` |
| 已学 | 至少有一条 `mastery_records` |
| 待学 | 等同“未学”；统计接口统一用 `active + 未删除 + 无掌握记录` |
| 今日到期 | `review_schedule.first_reviewed_at IS NOT NULL` 且 `next_review_date <= 本地今天`，且题目 `active`、未删除 |
| 新题 | `review_schedule.first_reviewed_at IS NULL`，且题目 `active`、未删除；新题不进入到期队列，单独计入新题队列 |
| 积压 | 今日到期总数超过每日复习上限时，未返回的到期题数量 |
| 掌握度 | 取该题**最近一条** `mastery_records.q` 的映射：q=2 不熟、q=4 熟悉、q=5 精通；无记录为未学 |
| 已精通 | 最近一条评分 q=5 |
| 错题 | `mistake_book` 中该题最近一条流水为 `added`，或按业务规则仍处于错题状态 |
| 连续打卡 | 从本地今天（若今天无记录则从昨天）向前连续、每天至少有一条 `mastery_records` 的天数 |
| 今天 | `Asia/Shanghai` 本地日期 `YYYY-MM-DD`；跨日以本地 00:00 为界 |
| 题目状态 | `draft` 草稿、`active` 正式、`archived` 归档；软删除由 `is_deleted` 表示 |
| 待审项状态 | `pending` 待审、`approved` 已通过、`rejected` 已拒绝、`merged` 已合并 |
| 知识条目 | `knowledge_points` 中的独立知识内容（概念/原理/结论/流程/对比/易错点），可按分类组织，与题目多对多关联 |
| 知识状态 | `draft` 草稿、`active` 正式、`archived` 归档；软删除由 `is_deleted` 表示 |
| AI 质检 | M3a 的题目/知识质量审查，输出问题类型、严重度、证据与建议；只做建议，人工最终决定 |
| 来源类型 | `manual` 手动、`import` 导入、`crawler` 爬虫、`ai` AI 生产 |
| 正确率（M2） | `mastery_records` 中 q≥3 的条数 / 总条数；按时间窗口统计 |
| 掌握度分布（M2） | 按每题最近一条 q 分组计数 |

> 口径变更必须同时更新本章、数据字典、统计接口和测试用例。

## 3. 用户角色与核心流程

### 3.1 角色

- **个人用户 / 管理员**：登录、管理题库与知识库、刷题复习、触发导入与爬虫、审核待审题目与知识条目、查看统计。
- **系统任务**：M1 仅处理手动触发的爬虫/导入任务；M2 增加定时调度与统计聚合。每日复习队列**按请求实时生成**，不依赖零点定时任务。

### 3.2 核心流程

1. **日常刷题**：前端请求筛选条件 → 后端取题（不下发答案）→ 用户自述或文字作答 → 翻看参考答案 → 三档自评 → 写 `mastery_records` → 按 10.4 规则决定是否更新 `review_schedule`。
2. **每日复习**：后端按 `next_review_date <= 本地今天` 拉取到期题 → 合并新题 → 前端展示今日队列 → 评分后按 SM-2 重算间隔。
3. **本地导入入库**：选择文件/粘贴文本 → 后端同步解析切题并抽取知识条目 → 逐行校验 → 清洗 → 精确 + 近似去重 → 写入 `pending_items`（题目/知识）→ 人工通过/拒绝/合并 → 写入 `questions` / `knowledge_points` 及对应来源表。
4. **爬虫入库**：配置源 → 触发任务 → 采集 raw Markdown/公开页 → 解析切题并抽取知识条目 → 清洗 → 精确 + 近似去重 → 规则建议标签/分类 → 写入 `pending_items`（题目/知识）→ 人工确认 → 写入 `questions` / `knowledge_points` 及对应来源表，并建立题-知识关联。
5. **知识条目审核**：待审区按 `item_type=knowledge` 展示建议标题、内容、分类、来源和相似条目；通过后进入知识库，合并时保留全部来源。
6. **仿真面试（M3）**：限定范围/题量/时长 → 随机抽题 → 逐题文字作答 → AI 评分追问 → 生成报告 → 回写薄弱点/错题本/复习队列。
7. **统计复盘**：仪表盘展示已学/待学/到期/错题/掌握度分布/连续打卡；知识库展示题-知识覆盖率。
8. **考前冲刺**：按公司/频率/分类选范围，忽略到期日期生成练习集；评分照常写入掌握记录，但只有在题目到期或评为“不熟”时才改变排程。

### 3.3 队列生成原则

- 队列在请求时实时计算，不物化“每日队列”表。
- 到期题优先，按 `next_review_date` 升序；新题随后。
- 每日新题上限与复习上限来自 `app_settings`；到期题超过上限时只返回上限条，仪表盘显示积压数，不丢题。
- 同一题在同一个本地日只进入一次队列；已评分题当天不再重复出现。

## 4. 题目来源双轨设计

### 4.1 统一管线

两条来源轨道在“清洗之后”汇入同一条管线，保证去重、审核、审计逻辑只写一份：

```text
本地导入(手动/MD/CSV/JSON/粘贴) ──┐
                                    ├─→ 解析切题/抽取知识 → 清洗 → 精确去重 → SimHash 近似去重
GitHub 爬虫(M1) / 牛客爬虫(M2) ────┘        → 规则建议标签/分类 → pending_items(item_type=question|knowledge)
                                                          → 人工 通过/拒绝/合并
                                                          → questions + question_origins
                                                          → knowledge_points + knowledge_origins + question_knowledge
```

### 4.2 轨道 A：本地导入（M1）

**支持形式**：

1. **手动新建单题**：表单录入题干、答案、要点、分类、属性、公司、个人笔记；默认直接入 `active`，也可保存为 `draft`。设置项 `manual.new_to_pending` 开启时，手动新建先进入 `pending_items`。
2. **手动新建知识条目**：表单录入标题、内容、类型（概念/原理/流程/对比/易错点）、分类、来源；默认直接入知识库 `active`，也可保存为 `draft` 或送待审。
3. **文件批量导入**：
   - Markdown：约定问答格式（见附录 A.1），按标题/问答标记切分，并从定义/原理/对比段落抽取知识条目；
   - CSV：按固定列模板（见附录 A.2），一行一题；Excel 文件请另存为 UTF-8 CSV；
   - JSON：按约定数组结构（见附录 A.3）；可同时包含题目与知识条目（见附录 A.6）。
4. **批量粘贴**：文本框粘贴一段 Markdown 面经，复用 Markdown 切分与知识抽取逻辑。

**处理规则**：

- M1 导入为**同步执行**，单次上限默认 5 MB / 2000 行；超限返回 `413` 并提示拆分。M2 如需更大文件再引入异步任务。
- 每次导入生成一条 `import_batches` 记录（文件名、格式、状态、总行数、成功/失败数、文件哈希、操作人、时间）。
- 逐行解析，失败行进入错误报告（行号/记录号 + 原因），不影响其余行；批次状态为 `success` / `partial` / `failed`。
- 导入项带 `source_type=import`，记录来源文件名与行号或记录号。
- 题目与知识条目默认都进待审区 `pending_items`；设置项 `import.direct_to_active` 开启时，校验通过的**题目**可直接 `active`，但仍需走去重，并写入 `question_origins`；由导入产生的知识条目 M1 始终走待审，避免低质量知识直接入库。
- 文件编码：优先 UTF-8（含 BOM），检测失败时尝试 GB18030；仍失败则报“无法识别编码”。

### 4.3 轨道 B：爬虫采集

#### 4.3.1 源管理（M1 GitHub / M2 牛客）

- 支持新增 GitHub 仓库/目录/raw URL 源；M2 支持牛客公开列表/公开帖 URL。
- 可配置抓取频率、是否启用、请求间隔、超时、重试次数、单次最大文件数、自定义 User-Agent。
- `crawl_sources.url` 唯一；保存前做 URL 校验与 SSRF 防护（见 6.3）。
- 牛客源的 `source_kind` 使用 `nowcoder`，UI 显示“牛客”。

#### 4.3.2 任务与采集

- 手动触发 + 定时触发（定时调度 M2 实现，M1 仅手动）。
- 一个采集任务可覆盖多个文件；任务主表记录汇总，`crawl_task_files` 逐文件记录 URL、HTTP 状态、解析数、错误、缓存路径。
- 任务状态：`pending / running / success / partial / failed / canceled`。
- M1 采集使用 httpx；M2 动态页用 Playwright。
- 记录 HTTP 状态、耗时、错误日志；失败可重试，重试只处理失败文件，并生成带 `parent_task_id` 的新任务。
- 遵守 robots、限频、超时重试、标明 User-Agent，不绕过登录/付费。
- GitHub 采集建议使用一次递归 tree 请求列出文件，再下载 raw Markdown；支持可选 `GITHUB_TOKEN`，并缓存 ETag/Last-Modified，减少限流风险。

#### 4.3.3 解析、清洗与去重（导入与爬虫共用）

- Markdown 按标题/列表/问答启发式切分题目与答案；跳过 fenced code block，避免代码中的标题误切。
- 在切题的同时抽取知识条目：标题、内容、类型、分类、来源段落。M1 使用规则启发式（如“定义/原理/区别/流程/注意”等段落、加粗标题、列表）；低置信度进入待审人工修，M3 可用 AI 辅助抽取。
- 清洗广告、水印、表情、无关前后文。
- **精确去重**：`content_hash` 为题干（或知识标题+内容）归一化后的 SHA-256（全文统一使用该算法）。
- **近似去重**：SimHash，汉明距离阈值可配置（默认 ≤3）；建议对中文使用分词或字符 3-gram，阈值在真实语料上调。
- 一题可对应多个来源：来源与题目为多对多，写入 `question_origins`；知识条目来源写入 `knowledge_origins`；主表不设 `source_url` 唯一约束。
- 解析结果进入 `pending_items`，**不直接写入正式题库或知识库**。
- 去重语料：`active` + `archived` + 其他 `pending` + 本批次内；已软删除内容默认不参与，但审核界面提示“存在已删除相似项”，由人决定是否恢复。

#### 4.3.4 待审区（导入 + 爬虫 + 手动 + AI 共用）

- 唯一存储为 `pending_items`；用 `item_type` 区分 `question` 与 `knowledge`。展示原始内容、解析题干/答案或知识标题/内容、建议标签/分类/难度/频率、来源（文件名+行号 或 URL）、去重结果（命中的相似项）、解析置信度。
- 支持编辑、通过、拒绝、合并重复。
- 题目通过后写入 `questions`，状态 `active`，同时写入 `question_origins`，回填 `pending_items.created_question_id`；知识条目通过后写入 `knowledge_points`，写入 `knowledge_origins`，回填 `created_knowledge_id`。
- 通过题目时，可根据分类/标签/要点自动建议关联已有知识；审核人确认后写入 `question_knowledge`。通过知识条目时，可反向关联已有题目。
- 合并到已有题/知识时，向目标追加来源；是否替换答案/内容由审核人选择，默认保留原内容并把待审内容存入来源快照。
- 拒绝/删除保留审计记录。
- 支持按来源/批次批量删除；删除时移除对应 `question_origins` / `knowledge_origins`，若题目或知识条目已无任何来源，则归档而不是硬删除。
- M3a 可在此处增加 AI 质量审查结果（事实错误、过时、歧义、答案不完整、知识不一致等），仅作建议，不改变人工审核的最终决定。

### 4.4 归一化、去重与合并规则

**归一化**：

- Unicode NFKC；去除零宽字符；合并连续空白；去除首尾空白；
- 是否去除 Markdown 标记由实现决定，但**不得删除代码运算符**（如 `+`、`-`、`*`、`/`）；
- 英文可选转小写；中文不做同义词替换；
- 归一化规则必须版本化，变更后旧 `content_hash` 可保留但不再用于精确判断。

**精确去重**：归一化题干哈希相同即命中。

**近似去重**：SimHash 命中后不自动合并，只在待审区展示相似题，由人确认。

**合并策略**：

- 同题不同答案：默认保留原答案，将新答案写入 `question_origins.raw_snapshot`；审核人可手动替换答案；
- 同批次内重复：保留一条 `pending`，其余标记 `merged` 并记录 `dup_of_pending_id`；
- 合并后来源必须全部保留，禁止因合并丢失来源 URL/文件名。

**知识条目去重与合并**：

- 知识条目以“归一化标题 + 内容”计算精确哈希；内容 SimHash 用于近似重复；
- 标题同义但内容不同的条目默认不自动合并，只在待审区提示；
- 合并知识条目时保留全部 `knowledge_origins`，并保留别名/同义标题，避免搜索丢失；
- 题-知识关联使用 `question_knowledge.relation_type`（`related` / `prerequisite` / `derived_from`），默认 `related`。

### 4.5 规则打标

M1 不依赖 AI，但必须给出可执行的规则建议：

- `tag_rules` 表保存关键词 → 标签/分类/难度/频率/权重的规则；允许 `contains` 与 `regex` 两种匹配。
- 启动时从 `config/tag_rules.yaml` 加载种子规则；后台设置页可增删改。
- 对每条待审项匹配所有启用规则，输出 `suggested_meta` JSON：

```json
{
  "tags": ["TCP", "计算机网络"],
  "category_id": 12,
  "difficulty": 3,
  "frequency": "high",
  "confidence": 0.8,
  "matched_rules": [1, 3]
}
```

- `parse_confidence` 记录解析器对切分质量的置信度（0–1），低置信度项在待审列表置顶提示。
- 知识条目同样使用规则建议分类与标签；`suggested_meta` 增加 `item_type` 与 `knowledge_category_id` 字段。
- 验收：20 条样例待审项中至少 15 条至少命中一个建议标签或分类；建议可编辑、可忽略。

### 4.6 导入导出回环

- 导出 Markdown 使用附录 A.1 格式；导出 JSON 使用附录 A.3 / A.6 格式，包含题目、知识条目与题-知识关联。
- 导出文件必须能被同一版本重新导入，且题干、答案、要点、分类路径、标签、难度、频率、公司、知识标题/内容/类型/关联不丢失。
- 增加“导出 → 再导入 → 对比”的自动化测试；ID、时间、掌握记录不要求回环。

### 4.7 知识条目抽取与入库（M1）

**知识条目的定义**：可独立复用的知识内容，例如概念定义、原理、流程、对比、常见误区；不是题目答案的简单复制，也不是三级分类节点本身。

**来源**：

- 手动新建；
- 导入 JSON 中的 `knowledge` 数组（附录 A.6）；
- Markdown/CSV 导入与爬虫内容中的定义、原理、对比、流程、注意事项段落；
- 题目审核通过时，从 `key_points`、答案中的结构化要点抽取候选项。

**M1 规则抽取**：

- 识别加粗标题、列表项、“定义/原理/区别/流程/注意/为什么”等关键词段落；
- 生成候选知识条目的标题、内容、类型、建议分类和来源段落；
- 置信度低的候选项进入待审区并置顶；不自动入库。

**审核与关联**：

- `pending_items.item_type='knowledge'` 的项通过后写入 `knowledge_points` 与 `knowledge_origins`；
- 审核界面展示相似知识条目，支持合并；
- 题目与知识条目通过 `question_knowledge` 多对多关联；默认关系为 `related`，可标记 `prerequisite` / `derived_from`。

**去重**：

- 精确哈希基于“归一化标题 + 内容”；SimHash 用于近似重复；
- 同义标题不自动合并，由审核人确认，并保留别名。

**M3a AI 质检**：

- 对知识条目和题目做事实正确性、知识一致性、答案完整性、歧义与过时检查；
- 输出问题类型、严重度、证据、修改建议和置信度；
- 只写入质量检查记录和待审提示，不自动通过、不自动修改。

**验收**：

- 至少 20 条知识条目通过审核进入知识库；
- 至少 20 道题与知识条目建立关联；
- 知识库支持关键词搜索、按分类浏览、查看来源与关联题目；
- 同一知识条目重复导入能被哈希/SimHash 识别。

## 5. 功能需求与验收标准

### 5.1 题库管理与标签体系

**功能**：

- 题目 CRUD、软删除、归档与恢复；保存草稿。
- **分类树（3 级层级）**：方向 → 技术栈 → 知识点，可挂多个分类路径；同一父节点下名称唯一。
- **平铺属性**：难度 1–5、考察频率 高/中/低、对应公司（多选）。
- **自由标签**：多标签、组合筛选。
- **关键词搜索**：题干、答案、标签；M1 用 `LIKE`，M2 可升级 FTS5。
- **个人笔记**：每题一段自由文本，用于口诀、易错点、面试表达。
- 来源：手动新建、本地导入、爬虫采集、AI 生产（P2）。
- 题目状态：`draft / active / archived`；`is_deleted` 表示软删除。

**验收**：

- 单题字段完整：题干、参考答案、要点拆解、分类、自由标签、难度、频率、公司、个人笔记、掌握度、状态、来源、创建时间；
- M1 规模（≤500 题）组合筛选响应 ≤200ms；M2 规模（5000 题）≤300ms；
- 导入失败有逐行错误提示（行号/记录号+原因）；
- 软删除后历史掌握记录仍保留；
- 搜索“TCP”能命中题干或答案中包含该词的题。

### 5.2 主动刷题模式

**功能**：

- 按分类/自由标签/难度/频率/公司/掌握度/来源组合筛选生成练习集；
- 先隐藏答案，用户文字作答或自述后翻看参考答案；
- 三档自评：不熟 / 熟悉 / 精通，即时回写；
- 练习集接口不下发答案与要点，翻看时再请求题目详情；
- 支持“只看错题”“只看到期”“只看不熟”快捷视图。

**验收**：

- 自评后立即写入 `mastery_records`，并按 10.4 规则更新 `review_schedule`；
- 自评“不熟”自动进入错题本；
- 无 AI/断网时刷题闭环完整可用；
- 同一题同一天多次评分不会重复推进排程。

### 5.3 艾宾浩斯间隔重复（SM-2 改进）

**功能**：

- 每题维护 `reps`、`EF`、`interval_days`、`next_review_date`、`lapses`、`last_q`、历史评分；
- 每日生成“新学 + 到期复习”混合队列；
- 三档自评映射内部评分 q（见第 10 章）；不熟重置，精通拉长间隔；
- 每日新题/复习上限可配置；
- 到期提醒在 Web 仪表盘展示。

**验收**：

- 到期队列按 `next_review_date` 排序；
- 逾期题不重复叠加（同一题当天只出现一次）；
- 参数（EF 初值、下限、间隔上限、每日上限）可配置；
- 算法单元测试覆盖：不熟重置、熟悉推进、精通拉长、EF 下限 1.3、间隔封顶、同日防重、跨日边界。

### 5.4 错题本 / 收藏夹

- 答错或自评“不熟”自动进入错题本（记录入错时间、原因，移出保留流水）；
- 手动收藏重点题；
- 支持重练、移出、按来源筛选、导出 Markdown；
- 错题重练后写新的 `mastery_records`，错题本状态按最新自评更新（连续两次“熟悉/精通”可自动移出，可配置）；
- `mistake_book.reason` 区分 `unfamiliar`、`manual`、`auto_pass_twice`。

**验收**：错题重练后更新掌握记录；导出字段完整；移出操作有流水记录；自动移出有原因记录。

### 5.5 搜索、筛选与基础统计

- 关键词 + 分类/自由标签/难度/频率/公司/掌握度/来源任意组合；
- 仪表盘指标：已学、待学、今日到期、已精通、错题数、连续打卡；
- M2 增加掌握度分布、正确率趋势、错题知识点分布；
- 所有统计口径按 1.5 节执行，接口返回 `definitions_version` 便于排查。

**验收**：M1 仪表盘 6 个指标可查；统计接口响应 ≤500ms；搜索与筛选可组合。

### 5.6 本地导入（P0 必选，详见第 4 章与附录 A）

**M1 验收**：

- Markdown / CSV / JSON 三种格式各至少成功导入一次；
- 构造含 2 行错误的文件，错误报告准确定位行号/记录号与原因，其余行正常进入待审区；
- 重复内容（与已有题/知识哈希相同 / SimHash 命中）被识别并标记，不重复入待审；
- 待审区可通过 ≥20 道导入题进入正式题库；
- 导入内容可抽取知识条目；至少 20 条知识条目进入知识库，并建立题-知识关联；
- 无 AI 时规则建议标签/分类可展示、可编辑；
- 同一文件重复上传能被 `file_hash` 识别并提示。

### 5.7 爬虫功能（P0 必选，详见第 4 章）

**M1 验收（GitHub）**：

- 配置至少 1 个 GitHub 面经仓库，采集 ≥50 个 raw Markdown 文件；
- 解析出 ≥100 道候选题，并抽取 ≥30 条候选知识条目；
- 精确去重与 SimHash 近似去重均生效；
- 待审区可通过 ≥20 道题进入正式题库，≥20 条知识条目进入知识库；
- 至少 20 道题与知识条目建立关联；
- 爬虫任务失败有日志和重试；逐文件状态可查；
- 无 AI 时规则打标可展示、可编辑；
- 确定性验收使用仓库固定 commit 的 fixtures；真实仓库采集作为演示，不作为唯一验收依据。

### 5.8 考前冲刺

- 入口：题库或仪表盘的“冲刺”按钮；
- 选择公司、分类、频率、题量；忽略 `next_review_date`，从匹配题中随机或按频率抽题；
- 默认不改变排程；评分仍写入 `mastery_records`；
- 若评分为“不熟”，按 10.4 规则重置排程；若题目本来到期，也按正常规则推进；
- 显示倒计时/目标日期（可选），帮助安排面试前复习。

**验收**：能生成冲刺练习集；评分记录可查；未到期题的正常评分不改变排程。

### 5.9 大模型能力（P2 增强）

| 能力 | 触发 | 输出 |
|---|---|---|
| **题目/知识质量审查** | 待审审核时 / 手动触发 | 事实错误、过时信息、歧义、答案不完整、知识不一致、重复冲突；严重度、证据、修改建议、置信度 |
| 错题解析 | 答错/不熟 | 拓展讲解、关联知识点、2–3 道追问 |
| 模拟面试官 | 仿真面试 | 压力追问、逐题评分、建议 |
| 题库生产 | 指定知识点 | 题目+答案+考点拆解，进待审区 |
| 自动打标 | 爬虫/导入/新题 | 推断分类、难度、频率 |
| 周报告 | 每周/手动 | 薄弱点+下周计划 |
| 答案润色 | 手动 | 面试可复述要点 |

**质量审查的输出约束**：

- 使用 JSON Schema 校验，至少包含 `target_type(question/knowledge)`、`target_id`、`issues[]`、`overall_risk(low/medium/high)`；
- 每个 issue 包含 `type`、`severity`、`description`、`evidence`、`suggestion`、`confidence`；
- **只作建议**：不得自动通过、拒绝、修改或删除题目/知识；最终由人工审核；
- 质量审查结果写入 `quality_checks`，在待审区和详情页展示徽标；
- M1/M2 不启用；M3a 接入，AI 不可用时不影响人工审核。

**通用要求**：OpenAI 兼容接口、prompt 版本化、JSON Schema 校验、缓存、超时重试、失败降级、token/成本记录。**AI 输出不得直接入正式题库或知识库，一律进待审区或质量检查记录。** 发送用户答题记录前需显式同意；支持脱敏。

### 5.10 仿真模拟面试（P2 / M3b）

- 组卷：范围、题量、时长、随机抽题；
- 流程：逐题展示 → 计时文字作答（M4 可选录音）→ 提交；
- AI 逐题评分、追问、指出遗漏；
- 报告：总分、逐题得分、亮点、知识缺口、建议、薄弱点清单回写错题本/复习队列；
- AI 失败时支持手动评分并生成基础报告。

**验收**：完成 5 题文字面试并生成报告；报告可回写薄弱点。

### 5.11 知识条目库（M1）

**功能**：

- 知识条目 CRUD、软删除、归档与恢复；保存草稿。
- 字段：标题、内容、类型（概念/原理/流程/对比/易错点）、分类、别名/同义标题、来源、关联题目。
- 知识条目可手动新建，也可由导入/爬虫抽取后进入待审区。
- 知识库支持关键词搜索、按分类浏览、查看来源与关联题目。
- 题目详情页展示关联知识；知识详情页展示关联题目。
- 题-知识关联支持 `related` / `prerequisite` / `derived_from` 三种关系。
- 知识条目不参与 SM-2 复习（M1）；后续如需“知识卡片复习”再单独设计。

**验收**：

- 至少 20 条知识条目通过审核进入知识库；
- 至少 20 道题与知识条目建立关联；
- 同一知识条目重复导入能被哈希/SimHash 识别；
- 知识搜索、分类浏览、来源查看、关联题目查看可用；
- 知识条目导出后可重新导入，标题、内容、类型、分类、别名、关联不丢失。

## 7. 数据模型

> M1 用 SQLite，DDL 以通用类型书写；M2 迁 PostgreSQL 时注意：布尔、时间戳、JSON 字段的方言映射，Alembic 管理迁移。
> 本章 DDL 是唯一模型来源；其他章节只引用字段，不另行定义。

### 7.1 实体关系（文字 ER）

- `users` 1—N `auth_sessions`（M1 单用户）；
- `categories` 自关联树：方向(level1) → 技术栈(level2) → 知识点(level3)；
- `questions` N—N `categories`（`question_categories`）；
- `questions` N—N `tags`（`question_tags`）；
- `questions` N—N `companies`（`question_companies`）；
- `questions` 1—N `question_origins`（来源溯源）；
- `knowledge_points` N—1 `categories`（知识条目可挂一个分类；M2 可扩展多分类）；
- `questions` N—N `knowledge_points`（`question_knowledge`，支持 `related/prerequisite/derived_from`）；
- `knowledge_points` 1—N `knowledge_origins`（知识来源溯源）；
- `questions` 1—1 `review_schedule`；
- `questions` 1—N `mastery_records`；
- `questions` 1—N `mistake_book`、1—N `bookmarks`；
- `pending_items` 统一承载手动/导入/爬虫/AI 待审项，用 `item_type` 区分题目与知识；通过后创建 `questions` 或 `knowledge_points`，并回填 `created_question_id` / `created_knowledge_id`；
- `crawl_sources` 1—N `crawl_tasks`；`crawl_tasks` 1—N `crawl_task_files`；
- `import_batches` 记录每次文件导入；`question_origins` / `knowledge_origins` 关联批次或任务。

### 7.2 核心表 DDL 草案

```sql
-- SQLite 连接级配置（每个连接执行）
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = NORMAL;

-- 用户（M1 单用户）
CREATE TABLE users (
    id            INTEGER PRIMARY KEY,
    username      TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 登录会话（服务端可撤销）
CREATE TABLE auth_sessions (
    id          INTEGER PRIMARY KEY,
    user_id     INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    token_hash  TEXT NOT NULL UNIQUE,
    created_at  TEXT NOT NULL DEFAULT (datetime('now')),
    expires_at  TEXT NOT NULL,
    revoked_at  TEXT
);

CREATE INDEX idx_auth_sessions_expires ON auth_sessions(expires_at);

-- 分类树：1 方向 / 2 技术栈 / 3 知识点
CREATE TABLE categories (
    id         INTEGER PRIMARY KEY,
    parent_id  INTEGER REFERENCES categories(id) ON DELETE RESTRICT,
    name       TEXT NOT NULL COLLATE NOCASE,
    level      INTEGER NOT NULL CHECK (level IN (1,2,3)),
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (parent_id, name)
);

CREATE UNIQUE INDEX uq_categories_root_name
    ON categories(name) WHERE parent_id IS NULL;

-- 自由标签
CREATE TABLE tags (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE COLLATE NOCASE,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 公司字典
CREATE TABLE companies (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE COLLATE NOCASE,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 导入批次
CREATE TABLE import_batches (
    id          INTEGER PRIMARY KEY,
    filename    TEXT,
    format      TEXT NOT NULL CHECK (format IN ('md','csv','json','paste')),
    status      TEXT NOT NULL DEFAULT 'processing'
                CHECK (status IN ('processing','success','partial','failed')),
    total_rows  INTEGER NOT NULL DEFAULT 0,
    ok_rows     INTEGER NOT NULL DEFAULT 0,
    fail_rows   INTEGER NOT NULL DEFAULT 0,
    file_hash   TEXT,
    operator    TEXT,
    error_log   TEXT,                   -- 逐行错误 JSON
    created_at  TEXT NOT NULL DEFAULT (datetime('now')),
    finished_at TEXT
);

-- 爬虫源
CREATE TABLE crawl_sources (
    id                INTEGER PRIMARY KEY,
    name              TEXT NOT NULL,
    source_kind       TEXT NOT NULL CHECK (source_kind IN ('github','nowcoder')),
    url               TEXT NOT NULL UNIQUE,
    enabled           INTEGER NOT NULL DEFAULT 1,
    user_agent        TEXT NOT NULL DEFAULT 'InterviewReviewBot/1.0 (+personal use)',
    interval_sec      INTEGER NOT NULL DEFAULT 10,
    timeout_sec       INTEGER NOT NULL DEFAULT 15,
    max_retries       INTEGER NOT NULL DEFAULT 3,
    max_files_per_run INTEGER NOT NULL DEFAULT 100,
    last_run_at       TEXT,
    next_run_at       TEXT,
    created_at        TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 爬虫任务（一次触发）
CREATE TABLE crawl_tasks (
    id             INTEGER PRIMARY KEY,
    source_id      INTEGER NOT NULL REFERENCES crawl_sources(id) ON DELETE CASCADE,
    parent_task_id INTEGER REFERENCES crawl_tasks(id) ON DELETE SET NULL,
    status         TEXT NOT NULL DEFAULT 'pending'
                   CHECK (status IN ('pending','running','success','partial','failed','canceled')),
    attempt        INTEGER NOT NULL DEFAULT 1,
    total_files    INTEGER NOT NULL DEFAULT 0,
    success_files  INTEGER NOT NULL DEFAULT 0,
    failed_files   INTEGER NOT NULL DEFAULT 0,
    log            TEXT,
    created_at     TEXT NOT NULL DEFAULT (datetime('now')),
    started_at     TEXT,
    finished_at    TEXT
);

-- 爬虫任务逐文件状态
CREATE TABLE crawl_task_files (
    id           INTEGER PRIMARY KEY,
    task_id      INTEGER NOT NULL REFERENCES crawl_tasks(id) ON DELETE CASCADE,
    url          TEXT NOT NULL,
    status       TEXT NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending','running','success','failed','skipped')),
    http_status  INTEGER,
    parsed_count INTEGER NOT NULL DEFAULT 0,
    error        TEXT,
    cached_path  TEXT,
    fetched_at   TEXT,
    UNIQUE (task_id, url)
);

-- 正式题库（含草稿）
CREATE TABLE questions (
    id            INTEGER PRIMARY KEY,
    stem          TEXT NOT NULL,          -- 题干
    answer        TEXT,                   -- 参考答案
    key_points    TEXT,                   -- 要点拆解(JSON 数组)
    notes         TEXT,                   -- 个人笔记/口诀
    difficulty    INTEGER CHECK (difficulty BETWEEN 1 AND 5),
    frequency     TEXT CHECK (frequency IN ('high','mid','low')),
    status        TEXT NOT NULL DEFAULT 'active'
                  CHECK (status IN ('draft','active','archived')),
    source_type   TEXT NOT NULL DEFAULT 'manual'
                  CHECK (source_type IN ('manual','import','crawler','ai')),
    content_hash  TEXT,                   -- 归一化题干 SHA-256
    simhash       TEXT,                   -- 64 位 SimHash 的十六进制表示
    is_deleted    INTEGER NOT NULL DEFAULT 0,
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at    TEXT NOT NULL DEFAULT (datetime('now'))
);

CREATE TABLE question_categories (
    question_id  INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    category_id  INTEGER NOT NULL REFERENCES categories(id) ON DELETE CASCADE,
    PRIMARY KEY (question_id, category_id)
);

CREATE TABLE question_tags (
    question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    tag_id      INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
    PRIMARY KEY (question_id, tag_id)
);

CREATE TABLE question_companies (
    question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    company_id  INTEGER NOT NULL REFERENCES companies(id) ON DELETE CASCADE,
    PRIMARY KEY (question_id, company_id)
);

-- 来源溯源：一题可多来源；审核通过/合并时写入
CREATE TABLE question_origins (
    id              INTEGER PRIMARY KEY,
    question_id     INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    source_type     TEXT NOT NULL CHECK (source_type IN ('manual','import','crawler','ai')),
    source_id       INTEGER REFERENCES crawl_sources(id) ON DELETE SET NULL,
    import_batch_id INTEGER REFERENCES import_batches(id) ON DELETE SET NULL,
    crawl_task_id   INTEGER REFERENCES crawl_tasks(id) ON DELETE SET NULL,
    origin_ref      TEXT,                 -- 文件名:行号 或 source_url
    raw_snapshot    TEXT,                 -- 原始答案/上下文快照
    content_hash    TEXT,
    fetched_at      TEXT,
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (question_id, source_type, origin_ref)
);

-- 掌握记录流水
CREATE TABLE mastery_records (
    id          INTEGER PRIMARY KEY,
    question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    q           INTEGER NOT NULL CHECK (q BETWEEN 0 AND 5),
    mode        TEXT NOT NULL DEFAULT 'practice'
                CHECK (mode IN ('practice','review','mistake','interview')),
    session_id  INTEGER,                  -- M3 面试/练习会话，M1 为空
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 复习排程（每题一行；创建题目/审核通过时初始化）
CREATE TABLE review_schedule (
    question_id       INTEGER PRIMARY KEY REFERENCES questions(id) ON DELETE CASCADE,
    reps              INTEGER NOT NULL DEFAULT 0,
    ef                REAL NOT NULL DEFAULT 2.5,
    interval_days     INTEGER NOT NULL DEFAULT 0,
    lapses            INTEGER NOT NULL DEFAULT 0,
    next_review_date  TEXT,               -- 'YYYY-MM-DD'，NULL 表示新题
    last_q            INTEGER CHECK (last_q BETWEEN 0 AND 5),
    last_rated_at     TEXT,
    last_schedule_date TEXT,              -- 最近一次推进/重置排程的本地日期
    first_reviewed_at TEXT,
    updated_at        TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 错题本流水
CREATE TABLE mistake_book (
    id          INTEGER PRIMARY KEY,
    question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    action      TEXT NOT NULL CHECK (action IN ('added','removed')),
    reason      TEXT CHECK (reason IN ('unfamiliar','manual','auto_pass_twice')),
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 收藏
CREATE TABLE bookmarks (
    id          INTEGER PRIMARY KEY,
    question_id INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    created_at  TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (question_id)
);

-- 知识条目库
CREATE TABLE knowledge_points (
    id           INTEGER PRIMARY KEY,
    title        TEXT NOT NULL,
    content      TEXT NOT NULL,
    kind         TEXT NOT NULL DEFAULT 'concept'
                 CHECK (kind IN ('concept','principle','process','comparison','pitfall','other')),
    category_id  INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    aliases      TEXT,                    -- JSON 数组：同义标题
    status       TEXT NOT NULL DEFAULT 'active'
                 CHECK (status IN ('draft','active','archived')),
    source_type  TEXT NOT NULL DEFAULT 'manual'
                 CHECK (source_type IN ('manual','import','crawler','ai')),
    content_hash TEXT,                    -- 归一化标题+内容 SHA-256
    simhash      TEXT,
    is_deleted   INTEGER NOT NULL DEFAULT 0,
    created_at   TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at   TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 题-知识多对多关联
CREATE TABLE question_knowledge (
    question_id   INTEGER NOT NULL REFERENCES questions(id) ON DELETE CASCADE,
    knowledge_id  INTEGER NOT NULL REFERENCES knowledge_points(id) ON DELETE CASCADE,
    relation_type TEXT NOT NULL DEFAULT 'related'
                  CHECK (relation_type IN ('related','prerequisite','derived_from')),
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    PRIMARY KEY (question_id, knowledge_id, relation_type)
);

-- 知识来源溯源
CREATE TABLE knowledge_origins (
    id              INTEGER PRIMARY KEY,
    knowledge_id    INTEGER NOT NULL REFERENCES knowledge_points(id) ON DELETE CASCADE,
    source_type     TEXT NOT NULL CHECK (source_type IN ('manual','import','crawler','ai')),
    source_id       INTEGER REFERENCES crawl_sources(id) ON DELETE SET NULL,
    import_batch_id INTEGER REFERENCES import_batches(id) ON DELETE SET NULL,
    crawl_task_id   INTEGER REFERENCES crawl_tasks(id) ON DELETE SET NULL,
    origin_ref      TEXT,                 -- 文件名:行号 或 source_url
    raw_snapshot    TEXT,                 -- 原始段落/上下文快照
    content_hash    TEXT,
    fetched_at      TEXT,
    created_at      TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (knowledge_id, source_type, origin_ref)
);

-- 统一待审区（手动 + 导入 + 爬虫 + AI 共用）
CREATE TABLE pending_items (
    id                  INTEGER PRIMARY KEY,
    item_type           TEXT NOT NULL DEFAULT 'question'
                        CHECK (item_type IN ('question','knowledge')),
    source_type         TEXT NOT NULL
                        CHECK (source_type IN ('manual','import','crawler','ai')),
    import_batch_id     INTEGER REFERENCES import_batches(id) ON DELETE SET NULL,
    crawl_task_id       INTEGER REFERENCES crawl_tasks(id) ON DELETE SET NULL,
    origin_ref          TEXT,             -- 文件名+行号/记录号 或 source_url
    raw_text            TEXT,
    stem                TEXT,
    answer              TEXT,
    knowledge_title     TEXT,
    knowledge_content   TEXT,
    suggested_meta      TEXT,             -- JSON：tags/category/difficulty/frequency/confidence
    parse_confidence    REAL CHECK (parse_confidence BETWEEN 0 AND 1),
    content_hash        TEXT,
    simhash             TEXT,
    dup_of              INTEGER REFERENCES questions(id) ON DELETE SET NULL,
    dup_of_pending_id   INTEGER REFERENCES pending_items(id) ON DELETE SET NULL,
    dup_of_knowledge_id INTEGER REFERENCES knowledge_points(id) ON DELETE SET NULL,
    created_question_id INTEGER REFERENCES questions(id) ON DELETE SET NULL,
    created_knowledge_id INTEGER REFERENCES knowledge_points(id) ON DELETE SET NULL,
    status              TEXT NOT NULL DEFAULT 'pending'
                        CHECK (status IN ('pending','approved','rejected','merged')),
    reviewer_note       TEXT,
    created_at          TEXT NOT NULL DEFAULT (datetime('now')),
    reviewed_at         TEXT
);

-- 规则打标
CREATE TABLE tag_rules (
    id          INTEGER PRIMARY KEY,
    keyword     TEXT NOT NULL,
    match_type  TEXT NOT NULL DEFAULT 'contains'
                CHECK (match_type IN ('contains','regex')),
    tag_id      INTEGER REFERENCES tags(id) ON DELETE CASCADE,
    category_id INTEGER REFERENCES categories(id) ON DELETE SET NULL,
    difficulty  INTEGER CHECK (difficulty BETWEEN 1 AND 5),
    frequency   TEXT CHECK (frequency IN ('high','mid','low')),
    weight      REAL NOT NULL DEFAULT 1.0,
    enabled     INTEGER NOT NULL DEFAULT 1,
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 运行设置（SM-2 参数、每日上限、导入开关等）
CREATE TABLE app_settings (
    key        TEXT PRIMARY KEY,
    value_json TEXT NOT NULL,
    updated_at TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 审计日志
CREATE TABLE audit_log (
    id          INTEGER PRIMARY KEY,
    actor       TEXT NOT NULL DEFAULT 'user',
    action      TEXT NOT NULL,
    target_type TEXT,
    target_id   INTEGER,
    detail      TEXT,
    created_at  TEXT NOT NULL DEFAULT (datetime('now'))
```

SQLite 运行要求：

- 每个连接执行 `PRAGMA foreign_keys = ON`；
- WAL 模式、`busy_timeout=5000`、`synchronous=NORMAL`；
- 写操作串行化，uvicorn 固定单 worker；爬虫写库与 API 写库通过应用层队列或锁串行；
- 备份使用 SQLite backup API 或 `VACUUM INTO`，不要在写入时直接复制数据库文件；
- `updated_at` 由应用层 `onupdate` 维护，或加触发器。

M2 数据量上来后，可视情况增加 FTS5 搜索索引与更多复合索引。

## 10. SM-2 间隔重复算法定义

### 10.1 三档自评 → 内部评分 q 映射

| 用户自评 | 内部 q | 行为 |
|---|---|---|
| 不熟 | 2 | 判定记忆失败：`lapses+1`，`reps` 清零，`interval_days=1`，进入错题本 |
| 熟悉 | 4 | 正常推进间隔，`EF` 不变 |
| 精通 | 5 | 正常推进间隔，`EF` 增加 0.1 |

> 算法层保留 q=0~5 兼容未来扩展，M1 UI 仅暴露 2/4/5。

### 10.2 参数（可在 `/settings` 配置）

| 参数 | 默认值 | 说明 |
|---|---|---|
| EF 初值 | 2.5 | 易记系数 |
| EF 下限 | 1.3 | 低于此值不再下降 |
| 第 1 次成功间隔 | 1 天 | reps=1 |
| 第 2 次成功间隔 | 6 天 | reps=2 |
| 间隔倍率 | EF | reps≥3 后 `interval = round(interval × EF)` |
| 间隔上限 | 90 天 | 面试场景建议 60–90；可配置到 180 |
| 每日新题上限 | 20 | 可配置 |
| 每日复习上限 | 50 | 可配置 |
| 每日排程推进次数 | 1 | 每题每本地日至多推进/重置一次 |

设置键建议：`sm2.ef_initial`、`sm2.ef_min`、`sm2.interval_cap_days`、`sm2.daily_new_limit`、`sm2.daily_review_limit`、`dedupe.simhash_threshold`、`manual.new_to_pending`、`import.direct_to_active`、`import.max_rows`、`import.max_bytes`、`review.early_advances`、`crawl.max_files_per_run`、`auth.token_ttl_minutes`。

### 10.3 更新公式

先根据本次评分更新 EF，再用更新后的 EF 计算间隔。这样公式与测试用例保持一致。

```text
本地今天 = Asia/Shanghai 的 YYYY-MM-DD

若 q < 3:
    lapses = lapses + 1
    reps = 0
    interval_days = 1
    ef 保持不变
否则:
    ef = ef + (0.1 - (5 - q) × (0.08 + (5 - q) × 0.02))
    ef = max(ef, 1.3)
    reps = reps + 1

    若 reps == 1:
        interval_days = 1
    否则若 reps == 2:
        interval_days = 6
    否则:
        interval_days = round_half_up(interval_days × ef)

    interval_days = min(interval_days, 间隔上限)

next_review_date = 本地今天 + interval_days 天
last_schedule_date = 本地今天
first_reviewed_at = first_reviewed_at 或 本地今天
```

说明：

- `round_half_up` 使用“四舍五入”，不要依赖语言的银行家舍入；Python 可用 `int(x + 0.5)`。
- q=4 时 EF 增量为 0，间隔按当前 EF 正常增长。
- q=5 时 EF 先增加 0.1，再用新 EF 乘间隔。
- q=2 时不更新 EF，但重置 reps 和 interval。

### 10.4 时区、提前复习与同日多次评分

**时区与日界**：

- “今天”是 `Asia/Shanghai` 本地日期；跨日以本地 00:00 为界。
- 存储时保留 UTC 时间戳；`next_review_date` 使用本地日期字符串。
- 补 23:59 与 00:01 的边界测试。

**何时推进排程**：

- 新题首次评分：推进排程（无论 q 值）。
- 到期题（`next_review_date <= 今天`）评分：推进排程。
- 未到期题的“熟悉/精通”评分：只写 `mastery_records`，更新 `last_q`/`last_rated_at`，**不改变** `reps`、`EF`、`interval_days`、`next_review_date`。
- 未到期题的“不熟”评分：视为遗忘，允许重置排程（`reps=0`、`interval_days=1`、`next_review_date=明天`、`lapses+1`），并进入错题本。
- 同一题同一个本地日：`last_schedule_date` 已等于今天时，不再推进或重置排程，只更新 `last_q` 和掌握记录。这样刷题、复习、错题重练不会重复加速。

**提前复习**：未到期题按上述规则处理；如果用户希望“提前复习也算”，可在设置中开启 `review.early_advances=true`，默认关闭。

### 10.5 队列生成

- **新题队列**：`active`、未删除、`review_schedule.first_reviewed_at IS NULL`；按创建时间倒序或随机。
- **到期队列**：`active`、未删除、`first_reviewed_at IS NOT NULL`、`next_review_date <= 本地今天`；按 `next_review_date` 升序。
- **合并顺序**：到期题在前，新题在后；可按设置交错（默认不交错）。
- **上限**：每日新题上限、复习上限来自设置；到期题超过上限时只返回上限条，并在 `review/summary` 返回积压数。
- **去重**：同一题在同一个本地日只返回一次；已评分题当天不再出现。
- 队列在请求时实时计算，不生成物化的“每日队列”表。

### 10.6 单元测试用例

1. 新题自评“精通”(q=5)：EF=2.6，reps=1，interval=1，next=明天，first_reviewed_at=今天。
2. 次日再次“精通”：EF=2.7，reps=2，interval=6。
3. 再次“精通”：EF=2.8，reps=3，interval=round(6×2.8)=17（**不是 15**）。
4. “熟悉”路径：q=4 时 EF 保持 2.5；第三次间隔为 round(6×2.5)=15。
5. 中途“不熟”：lapses+1，reps=0，interval=1，EF 不变，进错题本。
6. 连续 q=3 后 EF 不低于 1.3。
7. interval 封顶：构造接近上限的间隔，q=5 后不超过 90。
8. 同日两次评分：`last_schedule_date` 相同，第二次不改变排程。
9. 跨日边界：本地 23:59 与次日 00:01 的“今天”不同，到期队列变化正确。
10. 同一题当天不重复出现在到期队列。

## 12. 总体架构与部署

### 12.1 架构分层

```text
┌──────────────────────────────────────────────────┐
│ 前端 Vue3 + TS + Vite + Element Plus + ECharts     │
│ 仪表盘/题库/知识库/刷题/复习/错题/收藏/导入/爬虫/待审/统计/设置 │
└───────────────────────┬──────────────────────────┘
                        │ REST/JSON + cookie/token
┌───────────────────────▼──────────────────────────┐
│ 后端 FastAPI                                      │
│ 认证 / 题库 / 知识库 / 刷题 / 复习 / 错题 / 收藏 / 统计 │
│ 导入管线 / 爬虫管理 / 统一待审 / 规则打标 / AI 网关(预留) │
├──────────────────────────────────────────────────┤
│ 能力模块                                          │
│ 刷题引擎 / SM-2 引擎 / 导入解析 / 知识抽取 / 爬虫管线 │
│ 去重服务(哈希+SimHash) / 统计 / 导入导出 / 任务调度 │
├──────────────────────────────────────────────────┤
│ 数据层 SQLite(M1) → PostgreSQL(M2, 可选)          │
├──────────────────────────────────────────────────┤
│ 外部：本地文件 / GitHub raw / 牛客公开页 / LLM API │
└──────────────────────────────────────────────────┘
```

### 12.2 运行与部署（Docker 放在最后）

#### 12.2.1 开发期（W1–W5，本地运行）

- 后端：Python venv + `uvicorn app.main:app --reload`，SQLite 文件放在项目 `data/` 下。
- 前端：`npm run dev`，Vite 代理 `/api` 到后端。
- 不引入 Docker；这样调试和热更新最快，避免早期把时间花在容器网络上。
- CI 只跑 lint、类型检查、单元/接口测试和前端构建，不构建镜像。

#### 12.2.2 交付期（W6 最后阶段，Docker Compose）

- 服务：`web`（前端静态产物由 nginx 托管）、`api`（FastAPI + uvicorn 单 worker）。
- 数据卷：使用命名卷挂载 SQLite 文件目录与导出目录；Windows 下避免直接用绑定挂载写 SQLite。
- 环境变量：`APP_PASSWORD_HASH` 或首次启动口令、`TOKEN_SECRET`、`DB_PATH`、`GITHUB_TOKEN`（可选）、限频参数；AI Key 仅 M3 使用。
- 健康检查：`GET /healthz`。
- 容器使用非 root 用户运行。
- M1 不引入 Redis/Celery；爬虫/导入的异步任务用后台线程 + 数据库任务表实现。服务启动时把遗留 `running` 任务标记为 `failed`，避免僵尸任务。
- Docker 打包只在功能完成后的 W6 进行，不作为开发期前置条件。

### 12.3 SQLite 与任务并发

- WAL + `busy_timeout` + 单写者；uvicorn 固定单 worker，避免后台线程重复执行。
- 爬虫写库与 API 写库通过应用层队列/锁串行化；长事务拆小。
- 备份使用 SQLite backup API 或 `VACUUM INTO`；恢复前校验文件完整性。
- 数据库文件与备份目录分离；备份保留 7 份并至少一份异地副本。

### 12.4 安全默认值

- 默认只监听 `127.0.0.1`；如需局域网访问，必须加 HTTPS 或反向代理。
- CORS 白名单只允许前端来源。
- 登录限流：例如 5 次/分钟/IP，连续失败 10 次锁定 15 分钟。
- 口令哈希使用 Argon2id 或 bcrypt；初始用户由环境变量或 CLI 创建。
- Cookie 使用 HttpOnly、SameSite=Lax；如使用 cookie 认证，写操作加 CSRF token。
- Markdown 渲染消毒；前端禁止未消毒的 `v-html`。
- 文件上传限制大小、扩展名与 MIME；备份恢复仅管理员/CLI。

## 13. 决策记录（ADR）

| 编号 | 决策 | 备选方案 | 选择理由 / 后果 |
|---|---|---|---|
| ADR-01 | 主形态选 Web 前后端分离，放弃 Qt 桌面端 | Qt/PySide6 桌面、纯前端本地 | API 可复用于未来移动端；浏览器免安装；代价是需起本地服务 |
| ADR-02 | 爬虫列为 M1 P0，但确定性验收用 fixtures | 爬虫延后到 M2 | 面经是题库主要原料之一；固定 fixtures 降低外部仓库不稳定风险 |
| ADR-03 | 题目与知识双来源：本地导入 + 爬虫，统一进待审 | 导入直接入库、爬虫单独审核 | 统一去重与审核管线，逻辑只写一份；题目与知识同管线 |
| ADR-04 | 文件导入默认进待审区，而非直接入库 | 直接入库 | 导入内容质量参差，先审后入更稳；提供“直接入库”开关 |
| ADR-05 | AI 后置到 M3a；质量审查只做建议 | M1 就接大模型 | 降低依赖与成本；AI 仅增强，人工最终决定 |
| ADR-06 | M1 用 SQLite，M2 视需要迁 PostgreSQL | 一开始就 PG | 单机零依赖、易备份；PG 不是单用户 M1 的刚需 |
| ADR-07 | 单用户用“口令 + 短期服务端会话”，不做完整 JWT 体系 | 完整 JWT 刷新/鉴权 | 单用户场景过度设计；会话表支持撤销 |
| ADR-08 | 标签拆为“分类树 + 属性 + 自由标签” | 统一“六级标签” | 层级树需要 parent_id，属性是枚举/多对多，混用会导致建表错误 |
| ADR-09 | `pending_items` 是唯一待审区（题目/知识），`questions` 不设 `pending_review` | 待审内容直接放 questions | 生命周期清晰；审核字段不污染正式题库/知识库 |
| ADR-10 | 新增 `question_origins` / `knowledge_origins` 记录多来源 | 只在待审记录存来源 | 审核后仍能按来源/批次删除，满足溯源要求 |
| ADR-11 | 导入同步 + 限额，爬虫异步 | 导入也异步 | 导入需要逐行错误即时返回；限额控制阻塞时间 |
| ADR-12 | M1 仅 CSV，xlsx 作为 M2 可选 | M1 原生 xlsx | 减少解析依赖与验收面；Excel 可另存 CSV |
| ADR-13 | 业务日期用本地日期，排程每本地日至多推进一次 | 用 UTC 日期、允许多次推进 | 避免跨日歧义与同日重复加速 |
| ADR-14 | 规则打标用可配置 `tag_rules` | 硬编码关键词 | 可维护、可验收、无 AI 也能用 |
| ADR-15 | 爬虫任务逐文件记录 | 只记录任务汇总 | 支持定位失败文件、只重试失败项 |
| ADR-16 | M1 不预留 `user_id`，多人化时迁移 | 所有表预留 user_id | 单用户场景减少无用字段；未来迁移成本可控 |
| ADR-17 | 新增独立 `knowledge_points` 知识库，与题目多对多关联 | 只做三级知识点分类 | 知识可独立检索、复用和质检；分类树仍保留 |
| ADR-18 | AI 质量审查放在 M3a，只做建议 | 入库前强制 AI 通过 | 避免 AI 误判阻塞入库；人工审核仍是最终关口 |
| ADR-19 | Docker Compose 放在 W6 最后阶段 | W1 就容器化 | 开发期本地运行更快；容器化只影响交付，不影响功能开发 |

## 15. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| GitHub raw/API 限流或封禁 | 爬虫采不到数据 | 限频、随机间隔、缓存 ETag/Last-Modified、可选 `GITHUB_TOKEN`、失败退避；本地导入兜底 |
| 外部面经仓库改结构 | 验收/解析失败 | fixtures 固定 commit；解析器容错；真实仓库只做演示 |
| 牛客反爬/用户协议限制 | M2 爬虫不可用或合规风险 | 仅公开页、遵守 robots/协议、限频；保留手动粘贴/导入兜底；必要时放弃牛客爬虫 |
| 面经版权争议 | 合规风险 | 仅个人学习不商用、记录来源、不转载发布、支持按来源删除 |
| SimHash 误判/漏判 | 重复题/知识入库或漏合并 | 阈值可调；待审区展示相似命中由人确认；中文分词/3-gram |
| 规则抽取知识质量低 | 知识库充满低价值条目 | 只做候选、不自动入库；置信度排序；人工审核；M3a AI 质检辅助 |
| 知识条目与题目不一致 | 复习内容冲突 | 题-知识关联由人确认；AI 质检提示不一致；保留来源快照 |
| AI 质检误判/漏判 | 错题或错误知识放行 | 只做建议、不自动通过；金标样本评估；人工最终审核 |
| 爬虫内容提示注入 | AI 被恶意文本诱导 | AI 输入隔离、System Prompt 约束、JSON Schema 校验、输出只进建议记录 |
| 规则打标质量低 | 审核负担增加 | 规则可配置、可编辑；验收只要求建议而非自动通过 |
| SQLite 并发写 | 锁等待/任务失败 | WAL、busy_timeout、单写者/串行化、单 worker |
| 导入编码/模板不规范 | 导入失败 | UTF-8/GB18030 检测、逐行错误、模板校验、示例文件 |
| AI 成本/接口不稳定 | M3 功能不可用 | 网关超时重试、缓存、失败降级手动、AI 不进核心链路 |
| SSRF/XSS/弱口令 | 本地服务被攻击 | URL 白名单/私网拦截、Markdown 消毒、登录限流、仅监听本机 |
| 数据丢失 | 复习记录丢失 | 在线备份、保留 7 份、恢复演练 |
| 范围蔓延 | M1 交付延期 | 严守 2.2 不做清单；新需求进 backlog；W6 buffer |
| 题库内容不足 | 成功指标达不到 | W3–W6 并行准备内容；导入/爬虫双轨；先保证 100 题 |

## 16. 术语表

| 术语 | 含义 |
|---|---|
| SM-2 | SuperMemo 2 间隔重复算法，按记忆效果动态调整复习间隔 |
| 三档自评 | 用户对一题的主观评价：不熟 / 熟悉 / 精通 |
| q | SM-2 内部记忆质量分（0–5），三档自评映射为 2/4/5 |
| EF | Easiness Factor 易记系数，默认 2.5，下限 1.3 |
| SimHash | 相似度指纹算法，汉明距离 ≤3 视为近似重复（阈值可调） |
| 待审项 | `pending_items` 中的候选题目或知识条目，人工审核后才入正式题库/知识库 |
| 知识条目 | `knowledge_points` 中可独立复用的知识内容（概念/原理/流程/对比/易错点） |
| 知识库 | 由知识条目组成、可按分类检索、与题目多对多关联的内容库 |
| 来源溯源 | 通过 `question_origins` / `knowledge_origins` 记录内容与文件名/URL/批次/任务的关系 |
| AI 质检 | M3a 对题目/知识做事实、一致性、完整性、歧义与过时检查；只给建议，人工最终决定 |
| 质量检查记录 | `quality_checks` 中保存的 AI 质检结果，不改变审核状态 |
| 分类树 | 方向→技术栈→知识点 的三级层级结构 |
| 掌握度 | 最近一次评分的三档映射：不熟/熟悉/精通；无记录为未学 |
| 已学 | 至少有一条掌握记录 |
| 待学 | active、未删除、无掌握记录 |
| 已精通 | 最近一次评分为 q=5 |
| 今日到期 | `next_review_date <= 本地今天` 且已首次复习 |
| 新题 | `first_reviewed_at IS NULL` 的 active 题 |
| 积压 | 到期题超过每日复习上限时未返回的数量 |
| 连续打卡 | 按本地日期连续、每天至少一条掌握记录的天数 |
| 今天 | `Asia/Shanghai` 本地日期；跨日以本地 00:00 为界 |
| 冲刺模式 | 忽略到期日期、按范围抽题的考前复习视图 |
| 规则打标 | 用 `tag_rules` 关键词规则给出标签/分类/难度/频率建议，不依赖 AI |
| 导入批次 | 一次文件/粘贴导入的 `import_batches` 记录 |
| 爬虫任务 | 一次采集触发的 `crawl_tasks` 记录，逐文件状态在 `crawl_task_files` |

## 附录 A. 本地导入模板规范

### A.1 Markdown 格式（问答切分约定）

```markdown
## 题目：什么是 TCP 三次握手？
**答案**：三次握手是……
**要点**：SYN / SYN-ACK / ACK；为什么不是两次……
**标签**：计算机网络,TCP
**难度**：3
**频率**：high
**公司**：腾讯,字节

## 题目：进程和线程的区别？
**答案**：……
```

规则：

- 以行首 `## 题目：` 作为一题起点；代码块（```）内的标题不切分。
- `**答案**`、`**要点**`、`**标签**`、`**难度**`、`**频率**`、`**公司**` 为可选字段，需行首匹配；缺省留空，待审时补。
- 无标记的自由文本按相邻标题启发式切分，低置信度项在待审区置顶提示。
- 同一文件可包含多题；题目顺序保留。
- 文件编码 UTF-8；允许 BOM。

### A.2 CSV 列模板（一行一题）

| 列名 | 必填 | 说明 |
|---|---|---|
| stem | 是 | 题干 |
| answer | 否 | 参考答案 |
| key_points | 否 | 要点，分号分隔 |
| category_path | 否 | 如 `计算机网络/TCP/三次握手`，按 / 匹配或新建分类 |
| tags | 否 | 逗号分隔自由标签 |
| difficulty | 否 | 1–5 |
| frequency | 否 | high/mid/low |
| companies | 否 | 逗号分隔公司 |

规则：

- 编码优先 UTF-8（含 BOM），检测失败尝试 GB18030；分隔符默认逗号。
- 含逗号、分号、换行的字段必须按 CSV 规范加引号。
- 错误报告使用“记录号”（表头后第 1 条数据为 1），并在详情中附物理行号。
- M1 不直接解析 `.xlsx`；Excel 请另存为 CSV。

### A.3 JSON 格式

```json
[
  {
    "stem": "什么是进程？",
    "answer": "……",
    "key_points": ["资源分配单位", "独立地址空间"],
    "category_path": ["操作系统", "进程管理", "进程基础"],
    "tags": ["OS", "基础"],
    "difficulty": 2,
    "frequency": "high",
    "companies": ["阿里"]
  }
]
```

规则：

- 顶层为数组；每项一个对象；`stem` 必填。
- `category_path` 为字符串数组，按层级顺序匹配或新建；允许 1–3 级。
- `key_points`、`tags`、`companies` 为字符串数组。
- 错误报告使用数组下标（从 0 开始）和字段名。
- 可选 `schema_version` 字段，便于未来升级。

### A.4 导出回环

- Markdown 导出与 A.1 完全一致；JSON 导出与 A.3 / A.6 完全一致。
- 导出时不写内部 ID；导入时重新生成。
- 自动化测试覆盖：导出 → 导入 → 逐字段对比（题干、答案、要点、分类路径、标签、难度、频率、公司、知识标题/内容/类型/别名、题-知识关联）。

### A.5 规则打标配置示例

```yaml
rules:
  - keyword: "三次握手"
    tags: ["TCP", "计算机网络"]
    category_path: "计算机网络/TCP"
    difficulty: 3
    frequency: high
    weight: 1.0
  - keyword: "进程|线程"
    match_type: regex
    tags: ["操作系统"]
    category_path: "操作系统/进程管理"
    difficulty: 2
    frequency: high
    weight: 0.8
```

- 启动时加载到 `tag_rules`；分类/标签不存在时按配置自动创建或跳过并记录警告。
- 建议结果写入 `pending_items.suggested_meta`，不自动写入正式题或知识库。
- 知识条目可增加 `item_type: knowledge` 与 `knowledge_category_path`，复用同一规则表。

### A.6 知识条目与组合 JSON 格式

知识条目单独导入时，使用数组：

```json
[
  {
    "title": "TCP 三次握手",
    "content": "客户端发送 SYN，服务端返回 SYN-ACK，客户端再发送 ACK……",
    "kind": "process",
    "category_path": ["计算机网络", "TCP"],
    "aliases": ["三次握手", "TCP 握手"]
  }
]
```

题目、知识条目与关联一起导出/导入时，使用组合对象：

```json
{
  "schema_version": 1,
  "questions": [
    {
      "stem": "为什么 TCP 需要三次握手？",
      "answer": "……",
      "key_points": ["同步双方序列号", "确认双方收发能力"],
      "category_path": ["计算机网络", "TCP", "连接管理"],
      "tags": ["TCP"],
      "difficulty": 3,
      "frequency": "high",
      "companies": ["腾讯"]
    }
  ],
  "knowledge": [
    {
      "ref": "kp-tcp-handshake",
      "title": "TCP 三次握手",
      "content": "……",
      "kind": "process",
      "category_path": ["计算机网络", "TCP"],
      "aliases": ["三次握手"]
    }
  ],
  "links": [
    {
      "question_index": 0,
      "knowledge_ref": "kp-tcp-handshake",
      "relation_type": "related"
    }
  ]
}
```

规则：

- `knowledge[].ref` 仅在本文件中用于关联，导入后重新生成 ID。
- `links[].question_index` 指向 `questions` 数组下标；`knowledge_ref` 指向 `knowledge[].ref`。
- 单独导入题目时仍可使用 A.3 的数组格式；单独导入知识时使用本节数组格式。
- 导入时先校验引用完整性，再写待审区；无效引用进入逐行错误报告。
